Conventional Centralized Image Search

In typical image search systems, user images are uploaded raw to central cloud servers, creating a single point of failure and exposure.

• Raw pixels sent to cloud server
• Server performs CNN inference
• Original images cached or retained
• High risk of visual data leakage

Content-Free Protected Search (Our System)

Original pixels remain client-side. The retrieval server operates strictly on 512-D mathematical representations.

• 0 original image pixels sent to server
• Feature extraction occurs before transmission
• FAISS operates on protected coordinates
• Storage physically decoupled with AES-256 vault

How Content-Free Retrieval Works

“The query image was processed locally. Its protected visual representation was compared against indexed representations using FAISS. The system returned the highest-similarity image IDs. The original query image was not sent to the retrieval server.”

Retrieval Architecture:

1. Local Extraction: MobileNetV3 (1280-D) generates visual embeddings on the client device.
2. Representation Protection: 512-D orthogonal projection + calibrated noise applied before transmission.
3. Vector Similarity Search: FAISS IndexFlatIP matches cosine proximity against stored representations.
4. Authorized Dereferencing: Decoupled AES-256 storage releases matching database images strictly to cleared roles.
